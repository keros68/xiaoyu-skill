# Content, Modules, and Reference-Guided Design

Use for new figures and substantial redesigns. For a small revision, apply only the decisions affected by the request.

## Content before appearance

State the question the figure answers and the reading task: understand a method, compare alternatives, evaluate evidence, or connect findings. For each module, identify:

- the question or function it serves;
- the essential content and its source;
- the clearest representation: map, image, plot, schematic, or text;
- its input/output relationship to other modules;
- details that belong in the caption rather than the figure.

A module should do recognizable scientific work. Avoid adding a box merely because a manuscript subsection or software package exists. Show measured evidence, conceptual explanations, and hypothetical experiments distinctly without repeating long disclaimers in every box.

## Module combinations

| Relationship | Useful arrangement | Check |
|---|---|---|
| Sequential processing | Directional chain or staged rows | Each arrow corresponds to an actual dependency |
| Shared input, separate analyses | Shared band above unequal branches | Do not imply that parallel analyses depend on one another |
| Comparison | Aligned panels with common encodings | Extents, scales, dates, and legends support the comparison |
| Evidence convergence | Several inputs into a central inference | Preserve the difference between observation and interpretation |
| Main method plus validation | Large method panel and smaller validation panel | Validation is connected to what it evaluates |
| Overview and detail | Overview with linked insets | The link and spatial or conceptual support are unambiguous |
| Feedback or iteration | Loop only around repeated operations | No decorative cycles |

These are combinations, not templates to fill. Use mixed arrangements when justified. Module size follows importance, content density, and readability; only comparable elements need comparable dimensions.

Example: a remote-sensing framework can place comparable product maps in a shared upper group, then branch into an imagery-based reference assessment and a larger controlled sampling-design experiment. Actual map crops explain product differences better than decorative checkerboards. This structure is appropriate only when those are the study's actual relationships.

## Learn from supplied examples

Inspect the example itself, including its caption when available. Extract transferable choices: area allocation, reading order, typography, line hierarchy, use of boxes, palette roles, legend ownership, and information density. Separate these choices from the example's subject matter.

Do not copy its scientific claims, software logos, fixed panel count, or exact palette merely to imitate its appearance. A serif font, blue/yellow accents, black frames, or asymmetric layout can be useful without becoming universal requirements.

If a draft looks generic, diagnose the cause first: equal emphasis on unequal work, repetitive boxes, unsupported decorative imagery, weak subject-specific evidence, excessive title bars, or unreadably small labels. More generated art is not the default remedy.

## Brief and execution

For a major redesign, provide a short brief: figure role and message; included content; module relationships and relative sizes; available assets; intended width and style. One or two layout alternatives are useful only when they represent real scientific or reading-path choices.

Use the user's supplied case or established preferences to proceed. Ask when a missing source or conflicting interpretation prevents a sound decision, rather than requiring a routine A/B/C approval step. New material should not silently expand the scientific scope.
